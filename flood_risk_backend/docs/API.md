# API reference

Base URL (development): `http://127.0.0.1:8000`. Interactive documentation generated by FastAPI: `/docs` (Swagger) and `/redoc`.
All responses are JSON. Dates are ISO `YYYY-MM-DD`. **Nothing here is a forecast**: assessments describe rain that has already been observed
(or a hypothetical scenario) compared with each district's own history.

## Conventions

**Unknown is explicit.** A value that cannot be determined is `null` (never `0`, never `"low"`). Where a status exists it says why.

| `status` (assessment) | Meaning |
|---|---|
| `ok` | hazard, vulnerability and combined are all known |
| `insufficient_rainfall_data` | no rainfall for the district, or fewer than 80 % of the window's days were observed: no total, no hazard, no combined |
| `no_climatology` | a window total exists but the district has no baseline for that window/day: hazard and combined are `null` |
| `vulnerability_unavailable` | hazard is known but the district has no vulnerability (too few known historical years): combined is `null` |

**Errors.** Every error body is `{"detail": <string | list>}`. Validation errors (422) from FastAPI's own checks carry a list of
`{"loc": [...], "msg": "...", "type": "..."}` objects; errors raised by the application carry a string. Two error bodies carry extra fields:
503 *missing tables* adds `"missing_tables": [...]`, and `GET /health/ready` adds `"status"`, `"database"`, `"missing_tables"`.

| Status | When |
|---|---|
| 404 | unknown district id; or nothing stored for the requested date/window (see each endpoint) |
| 422 | invalid or out-of-range parameter, malformed date, `start` after `end`, `window_days` not one of `GET /windows`, invalid request body |
| 503 | required database tables are missing (run `scripts/seed_db.py`); database temporarily unavailable (locked / cannot open); ML report files missing or malformed; model metadata unreadable or untrained (`/model/metadata`) |
| 500 | unexpected database or server error. The body is generic (`"Internal database error."` / `"Internal server error."`); SQL and stack traces are written to the server log only |

The API **never creates tables**. A request against an uninitialised database answers 503 with the names of the missing tables.

CORS: origins from `CORS_ORIGINS`. `X-Total-Count` and `X-Result-Truncated` are exposed to browsers.

## Health

### `GET /health`
Liveness only. `200 {"status": "ok"}`. Unchanged since the original backend.

### `GET /health/ready`
Readiness: the database is reachable and every required table exists.
`200 {"status": "ok", "database": "ok", "tables": <int>}` or
`503 {"status": "not_ready", "database": "missing_tables", "missing_tables": [...], "detail": "..."}`.

## Reference data

### `GET /windows`
`200 {"windows": [3, 7, 15, 30], "meaning": "..."}`. Windows come from the imported `hazard_config.json`; if absent, from windows that already have stored
assessments; else `[]`. A window is the N days of observed rain ending on a date, not a forecast horizon.

### `GET /districts`
`200` list of districts ordered by id:
`{id, name, state, geometry, mean_elevation_m, elevation_std_m, mean_slope_deg, low_lying_frac, pop_density_km2}`.
`geometry` is a GeoJSON Polygon/MultiPolygon object. Terrain fields and `pop_density_km2` are `number | null` (null = unknown).
Terrain is stored and served but is **not** used in the main vulnerability or hazard calculation; population density is unverified and is not used.

### `GET /districts/{district_id}/flood-impact`
Historical seasonal flood impact, one record per district-year that has a label row, ordered by year.
`200` list of `{year, status, impact_class, affected_population, reporting_period, caveats[], year_note}`.

* `status`: `reported` | `no_reported_impact` | `unknown`. `unknown` is not zero and not Low.
* `impact_class`: `low|moderate|high|severe` (relative bands, not official categories) or `null`.
* `affected_population`: number or `null` (missing). `0` only when the source states zero.
* `year_note`: documented caveat for 2019 and 2020, else `null`. `caveats`: quality flags stored with the record.
* A known district with no label rows returns `[]` (this does not mean there were no floods).

Errors: `404` unknown district.

## Assessments

All three assessment-returning endpoints (`/assessments`, `/districts/{id}/assessment`, `/districts/{id}/history`) and `POST /assess` return objects of this shape:

```jsonc
{
  "district_id": 1, "district_name": "…", "as_of_date": "2023-07-05", "window_days": 3,
  "basis": "observed_window",                 // or "scenario"
  "status": "ok",                              // see the status table above
  "hazard": {"component_type": "rule_based", "level": 1 /*0..3 | null*/, "label": "Moderate" /*| null*/,
             "exceeded": "baseline quantile q75" /*| null*/, "window_rain_mm": 55.0 /*| null*/, "obs_fraction": 1.0 /*| null*/},
  "vulnerability": {"component_type": "empirical_history" /*| "ml_estimate"*/, "risk_class": "high", "expected_index": 2.0,
                    "proba": null, "shap_top_features": null, "model_version": null},   // the whole object is null when unavailable
  "combined": {"component_type": "rule_based_combination", "risk_class": "moderate" /*| null*/, "risk_score": 0.5 /*0..1 | null*/},
  "unavailable_reason": null,                  // plain-language reason when hazard and/or combined are unknown
  "disclaimer": "Not a forecast. …"
}
```

`window_rain_mm` is rounded to 2 decimals and `obs_fraction` to 3 (Python `round`, half-to-even). `risk_score` is an ordering index, not a probability.
With the default configuration `vulnerability.component_type` is `empirical_history` (`proba` and `shap_top_features` are `null`).

`window_days` must be an integer 1–366 **and** one of `GET /windows`, otherwise `422`.

### `GET /assessments`
All districts for one window and date.

| Parameter | Type | Notes |
|---|---|---|
| `window_days` | int, required | 1–366 and one of `/windows` |
| `date` | date, optional | default: the latest date that has assessments for this window |

`200` list ordered by `district_id` (the number of SQL queries does not depend on the number of districts).
`404`: no assessments computed yet (run `scripts/assess_safe.py`), or none for that date/window. `422`: invalid window/date.

### `GET /districts/{district_id}/assessment`
One district, one window. Parameters: `window_days` (required), `date` (optional; default latest stored).
`200` one assessment object. `404`: unknown district, or no assessment for that district/date/window. `422`: invalid window/date.

### `GET /districts/{district_id}/history`
Stored assessments for one district and window, **oldest first**.

| Parameter | Type | Notes |
|---|---|---|
| `window_days` | int, required | as above |
| `start`, `end` | date, optional | inclusive; `start` after `end` → `422`; `start == end` is valid |
| `limit` | int, optional | 1–3660, default 3660 (ten years of daily rows) |

`200` list. Headers: `X-Total-Count` (rows matching before `limit`) and, only when `limit` cut the list, `X-Result-Truncated: true`.
`404` unknown district. `422` invalid parameters.

### `POST /assess`  (hypothetical scenario)
"If the last N days had brought X mm." **Not stored, not a forecast.** Body:

```json
{"district_id": 1, "window_days": 7, "window_end_date": "2023-07-15", "window_rain_mm": 150}
```
`window_days` 1–366 and one of `/windows`; `window_rain_mm` 0–2000; `window_end_date` selects the seasonal baseline day. Response: an assessment object with
`basis: "scenario"` and a HYPOTHETICAL disclaimer. Without a baseline for that district/day, `status` is `no_climatology` (hazard and combined `null`).
Errors: `404` unknown district, `422` invalid body or window.

## Rainfall

### `GET /rainfall/coverage`
Per district: stored days, observed days, missing days (NULL, not zero), date span.
`200 {"districts": n, "districts_with_rainfall": n, "coverage": [{district_id, name, has_rainfall, first_date, last_date, days_stored, days_observed, days_missing, observed_fraction, reason}]}`.
Districts without rainfall have `has_rainfall: false` and a `reason`.

### `GET /rainfall/recent`
Recent observed IMD daily rainfall (stored separately from the historical station rainfall; not used to compute hazard levels and not used by the ML experiment).

| Parameter | Type | Notes |
|---|---|---|
| `district_id` | int, optional | unknown id → `404` |
| `start`, `end` | date, optional | `start` after `end` → `422` |
| `limit` | int | 1–10000, default 5000 |

`200 {"dataset", "total_matching", "returned", "limit", "filters": {district_id, start, end}, "observations": [{district_id, district, date, rainfall_mm, source}], "disclaimer"}`,
ordered by date then district.

## Methodology and model

### `GET /methodology`
Describes what is assessed, how components combine, the missing-data rules, year notes and what data is loaded right now
(`current_data`: counts, vulnerability sources, stored assessment rows, windows, `model_trained`). A corrupt model-metadata file is ignored here (logged), not fatal.

### `GET /model/metadata`
Metadata of a **trained** vulnerability model, if one was ever trained with `scripts/train_model.py`.
`503` with a "train_model.py" message when none exists; `503` when the metadata file is unreadable or has an unexpected structure.
No model is shipped; the default state is `503`.

### `GET /ml-experiment/summary`
The **experimental, retrospective** ML feasibility report (read from `ml/reports/`). It is not a prediction service and is separate from every assessment.

`200`:
```jsonc
{"status": "experimental_not_integrated", "n_rows": 0, "n_districts": 0,
 "attrition": {"labelled_district_years", "after_excluding_2019_snapshots", "with_any_rainfall_station", "with_at_least_30_rain_days", "rows_missing_static"},
 "class_counts": {"Low": 0, "Moderate": 0, "High": 0, "Severe": 0},
 "models": [{"model", "features", "accuracy", "balanced_accuracy", "macro_f1", "macro_f1_ci95": [lo, hi] /*| null*/, "ordinal_mae"}],
 "permutation_test": {"static_plus_rain": {"observed_macro_f1", "perm_mean", "perm_p95", "p_value"}, "rain_only": {…}},
 "predictions": [{"district_id": "…", "year": 2020, "actual_class": "Low", "logreg_prediction": "…", "random_forest_prediction": "…"}],
 "limitations": ["…"]}
```
Numbers above are placeholders; real values come from the shipped report. The `limitations` sentences are **computed from the report**, so they follow it when it changes.
`503` when `model_comparison.json` or `oof_predictions.csv` is missing, unparsable, or structurally invalid (the message says which and why).
Scheme reported: four classes, leave-one-district-out.

## Compatibility notes for the frontend
* Every field of the supplied `types.ts` is present with the stated nullability (`tests/test_frontend_contract.py`).
* Backend fields the TypeScript types do not declare (harmless): `unavailable_reason` on assessments, `year_note` on flood-impact records.
* The frontend client treats any `404` from `/flood-impact` as "endpoint unavailable"; the backend also returns `404` there for an unknown district id.
* The frontend client treats any `503` from `/model/metadata` as "model not trained"; a corrupt metadata file also yields `503`.
* An unexpected `500` produced outside the database layer is generated outside the CORS middleware, so a browser may report it as a network error.
